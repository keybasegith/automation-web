Thanks for testing it and for the detail — both issues are fixed in the attached version.

**1. Images**

They're attached in the `business-card-assets` folder:

| File | Size | Used for |
| --- | --- | --- |
| `keybase-logo.png` | 700×166 transparent PNG, 37 KB | Header logo — same on every card |
| `profile-background.jpg` | 1200×800 JPEG, 262 KB | Banner behind the headshot — same on every card |
| `profile.jpg` | 400×600 JPEG, 26 KB | Advisor headshot — one per person (the attached one is a sample) |

Put them anywhere on the server and point `assetBase` at that folder — it's in the same `CARD`
block at the bottom of the file:

```js
assetBase: "/images/businesscard/",
```

A bare file name resolves against `assetBase`; anything starting with `/` or `https://` is used
as-is, so you can also give each image a full URL and leave `assetBase` empty.

The card no longer breaks if an image is missing or blocked: the logo is simply dropped, the
banner falls back to a Keybase-green gradient, and the headshot falls back to the advisor's
initials. No broken-image icons.

**2. The .js file**

That was a QR-code library loaded from a public CDN (jsDelivr), which your network is blocking.
I've removed it. The QR code is now generated by the page itself and drawn as inline SVG, so the
new file makes **zero external requests** — no CDN, no web fonts, no analytics, no trackers. The
only things it loads are your three images from your own server. Output is identical to what the
library produced, and I've scan-tested the generated codes.

If your policy also blocks *inline* `<script>`, let me know and I'll send a no-JavaScript build
instead: a CSS-only flip and a pre-generated QR image per advisor.

**3. Two things I tightened for embedding into `tcard.aspx`**

- All the card's code now runs inside a self-contained wrapper, so it defines no global variables
  and can't clash with jQuery (`$`) or anything else already running on the page.
- Every element ID is prefixed `kb-`, so it can't collide with IDs already on your page.

I also fixed a layout bug you may have noticed — the office address ran underneath the QR button
in the header at certain screen widths.
